# Problem Radar — Business Discovery Framework

Problem Radar is now designed to answer four questions in order:

1. **What problems are repeatedly experienced in Nigeria?**
2. **Which reports represent independent evidence rather than duplicated coverage?**
3. **Which underlying mechanisms appear across multiple sectors?**
4. **Which hypotheses deserve direct customer validation before building?**

## Decision rule

A problem pattern is not treated as a business merely because it is frequent. A candidate must accumulate evidence for recurrence, affected users, economic cost, an identifiable payer, an existing workaround, and willingness to pay.

## MVP rule

Before significant engineering, attempt a narrow manual service that solves the identified pain. Measure demand, repeat usage, conversion, and willingness to pay.

## Expansion rule

If a validated mechanism works in one sector, test whether the same workflow transfers to another sector. This is how Problem Radar can discover a business capable of solving multiple Nigerian problems without assuming that one application should contain everything.

## Current pipeline

Raw signals → evidence audit → problem clusters → business validation map → cross-sector mechanisms → customer validation → manual MVP → software/product.
